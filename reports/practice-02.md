## Словарь рубрик

| Рубрика | По какому правилу присваивается |
| --- | --- |
| `priority` | Перекрёстки и приоритет: «перекрёстк», «преимуществ», «уступить», «главн», «равнозначн», номера 13.x |
| `signs` | Знаки, разметка, светофоры, регулировщик: «знак», «табличк», «разметк», «светофор», «5.19», «6.4», «8.17» |
| `movement` | Маневрирование, скорость, остановка, световые приборы: «обгон», «разворот», «скорост», «остановк», «12.1», «19.1» |
| `duties` | Обязанности водителей, учебная езда, перевозки: «обязанност», «документ», «ремн», «учебн езд», «перевозк» |
| `responsibility` | Ответственность и штрафы (в т.ч. КоАП): «штраф», «коап», «наказани», «лишени», «12.12», «12.15», «административн» |
| `general` **(по умолчанию)** | Всё, что не распознано. |

Правило — по ключевым словам внутри фрагмента. Слова обрезаны до основы, чтобы ловить падежи. LLM не используется.

## Замеры

| № | CHUNK_SIZE | CHUNK_OVERLAP | Чанков в индексе | hit-rate@3 | hit-rate@1 |
| - | ---------- | ------------- | ---------------- | ---------- | ---------- |
| 1 | 512 | 64 | 648 | 100% (5/5) | 100% (5/5) |
| 2 | 256 | 64 | 1473 | 100% (5/5) | 100% (5/5) |
| 3 | 1024 | 128 | 338 | 100% (5/5) | 100% (5/5) |

Менялся `CHUNK_SIZE`; в замерах 1 и 2 `CHUNK_OVERLAP = 64`, в замере 3 — `128` (пропорционально размеру фрагмента). `hit-rate@1` снимался с того же индекса командой:

```bash
python -c "from ingest import evaluate_retrieval; evaluate_retrieval(k=1)"
```

**Выбранные значения и основание.**

Приняты `CHUNK_SIZE = 512`, `CHUNK_OVERLAP = 64`.

Все три варианта дали 100% по `hit-rate@3` и `hit-rate@1` — на корпусе из 5 вопросов метрика упёрлась в потолок. Выбор сделан по компромиссу между числом фрагментов и размером чанка. Вариант 256/64 даёт 1473 чанка — в 2.3 раза больше, чем 512/64, при том же качестве. Вариант 1024/128 компактнее (338 чанков), но содержит слишком крупные фрагменты: в промпт на П6 уйдёт больше постороннего текста, что ударит по Context Precision. Принято 512/64 как компромисс, значение совпадает со стартовой точкой шаблона, но оставлено по числу из таблицы, а не по умолчанию.

## Уточнение метрики из технического задания

На П1 в README было объявлено `hit-rate@5 = 80%`. По замечаниям преподавателя метрика понижена до **`hit-rate@3 = 75%`**: k=3 чувствительнее на малом корпусе из двух документов (68 страниц), при k=5 нужный фрагмент попадает в выдачу почти при любой нарезке.

Первый замер на П2 дал **100%** (5 из 5). Причина расхождения: вопросы чернового набора сформулированы к найденным в корпусе местам, то есть заведомо «ближе» к тексту, чем вопросы живого пользователя. Целевое значение остаётся **75%** — 100% на 5 вопросах считается завышенным относительно реальных условий. Метрика будет переснята на П6, когда Gold Dataset расширится до 10+ вопросов и в него войдут вопросы по коротким разделам (приложения со знаками, где поиск слабее).
